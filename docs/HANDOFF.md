# מסירה לשיחה חדשה

מסמך המצב של הפרויקט, כדי ששיחה חדשה עם Claude תמשיך מאותה נקודה. קוראים אותו אחרי
`CLAUDE.md` ולפני `docs/SPEC.md`. ה-SPEC נשאר מקור האמת: כאן רק תמונת מצב, איך עובדים,
ומה פתוח. מעדכנים את המסמך בסוף כל סבב עבודה.

עודכן: 1.11.2026 (טפסים ידניים, מסמכים מ-Airtable, הוספת לקוח/נכס, תעודת זהות; מיגרציות עד 20 הוחלו).

## 3. מה בנוי

**מסד הנתונים** (`supabase/migrations/`): ספר חשבונות כפול (transactions/entries, טיוטה/נרשם/מבוטל;
תנועה שנרשמה לא משתנה, רק מבוטלת), הרשאות לפי מדינה (viewer/editor/finance) + admin/management,
`require_mfa` על כל טבלה, `audit_log`, קליטת דוחות (`import_sources`, `import_batches`, `import_rows`,
`commit_import_batch`, `void_import_batch`, `apply_import_lease`), `integrations`, איפוס דוחות איתי
(`reset_itai_imports`), audit על parties.

**ממשק המשרד** (`web/`, React + Mantine, RTL):
- לוח בקרה, נכסים (סינון מדינה/עיר/סטטוס/חיפוש), כרטיס נכס עם תנועות, לקוחות, כרטיס לקוח
  (פרטים ועריכה, נכסים, חשבונות, תנועות מתחילת 2026 עם יתרת פתיחה או הכול), חוזים (עריכה).
- **קליטת דוחות:** העלאת קובץ → adapter בדפדפן מפרק אותו → דוח לבדיקה (התאמת נכסים, שגיאות שצריך
  לסמן "בדקתי", כפילויות, החלפות וביטולים בדוח מעודכן, חוזים מהקובץ) → מי שיש לו finance מאשר רישום.
  ביטול דוח שנרשם, מחיקת דוחות ממתינים, מיון שורות, הסתרת דוחות שנדחו.
- **Adapters** (`web/src/intake/`): ויטאלי (קייב PLC, שכירות חודשית), גרשון (הוצאות + יתרות דולר),
  איתי (רומניה, קובץ לכל לקוח, שני מודלים: חוזה ישיר / חוזה eden, מע"מ, נוסחת איזון מול Totals,
  תרגום לעברית). שינוי מבנה בקובץ זורק `FormatError`, לעולם לא מייבא מספרים שגויים.
- **טפסים ידניים (החלטה 63):** ירח (העברות לגרשון, חלוקה יחסית לפי השכירות הצפויה) וליאנה (סכום
  חודשי לדירה, 10% עמלה, היתרה לבנק הלקוח). הלוגיקה ב-`web/src/intake/manual.ts` (עם בדיקות), הנתונים
  ב-`web/src/lib/manual.ts`, המסך ב-`web/src/components/ManualReport.tsx`. הטופס עצמו מסמן אילו דירות
  של המנהל ומה השכירות הצפויה (`management_agreements`, `rent_schedule`), בלי מיגרציה חדשה.
- **מסמכים של אנשים (החלטה 64):** צילומי ת"ז, דרכונים, ייפויי כוח וקבצים מצורפים מ-Airtable, בכרטיס
  הלקוח (רגישים בלבד). העתקה: `scripts/import/documents.ts` (בלי `--run`: ספירה בלבד) דרך פונקציית Edge
  `supabase/functions/airtable-documents`, שעובדת מתור `app.document_imports` (בלי קלט ובלי סוד), והמסד קורא לה ב-`pg_net`.
- **הוספה מהממשק (החלטה 65):** לקוח חדש (מסך לקוחות), נכס חדש (מסך נכסים או כרטיס לקוח, כולל בניין חדש
  ובעלים), והעלאת מסמכים בכרטיס הלקוח (`ClientForm`, `PropertyForm`, `ClientDocuments`).
- **תעודת זהות (החלטות 66, 72):** `app.party_identity` (פתוח לכל העובדים מאז החלטה 72; שם פרטי/משפחה ב-`parties`). זיהוי מסריקות בדפדפן: `web/src/lib/idnumber.ts`
  (ספרת ביקורת, MRZ; עם בדיקות) ו-`web/src/lib/idocr.ts` (tesseract.js + pdf.js, נטענים רק כשצריך).
  נבדק בדפדפן על דוגמאות סינתטיות; המודל יורד מ-CDN, שחסום בסביבת Claude (לבדיקה: `@tesseract.js-data/eng` מ-npm).
- **מחיקה (החלטה 67):** נכס, חוזה או לקוח בלי היסטוריה כספית, admin בלבד, עם סיבה והקלדת "מחיקה"

- **כרטיס חוזה (החלטה 68):** `/leases/:id` (`LeaseCard`), עם מסמכי החוזה דרך `EntityDocuments` (רכיב כללי
  למסמכים של רשומה אחת; מתאים גם לנכס).
- **פרטי נכסים (החלטה 70):** `scripts/import/property_details.ts` (אוקראינה וגאורגיה; `--run --no-files` בלי קבצים).
  משותף לסקריפטים: `scripts/import/lib/remote.ts` (Airtable, SQL, תור ההעתקה). רומניה: `scripts/import/romania_details.ts <choices.json>` (החלטה 71).

  `lib/completeness.ts` (הבדיקות, עם בדיקות יחידה) ו-`pages/Completeness.tsx`. מיגרציה 25.
- **שיוך אנשי קשר, פעולות, שותפים בחברה (החלטות 79–81):** `components/CardExtras.tsx`. מיגרציה 26.

## 4. איך עובדים (מה שלמדנו)

- **בדיקות:** `npm test` בשורש (ייבוא + מסד נתונים על Postgres מקומי + adapters). `cd web && npm run build`.
  בדיקות מסד הנתונים ב-`supabase/tests/access_control_test.sql`; כל מיגרציה חדשה מקבלת בדיקה.
- **החלת מיגרציה על Supabase:**
  `SUPABASE_ACCESS_TOKEN=sbp_dummy NODE_USE_ENV_PROXY=1 node scripts/supabase-sql.ts migrate`
  (ה-proxy של סביבת Claude מזריק את הטוקן האמיתי; `run <file.sql>` מריץ שאילתה).
- **מגבלות סביבת Claude:**
  - **Airtable:** `AIRTABLE_TOKEN` מוגדר בסביבה (קריאה), ו-`api.airtable.com` פתוח. קובצי Airtable
    (`*.airtableusercontent.com`) חסומים, ולכן קבצים עוברים דרך פונקציית Edge.
  - פעולות על הייצור (מיגרציה, פריסת פונקציה, הרצת ייבוא) דורשות אישור מפורש של יוסי בשיחה.
  - הכתובת `*.supabase.co` חסומה מהסביבה: אי אפשר לפתוח את האתר מול הנתונים האמיתיים, רק לבנות.
    שאילתות עוברות דרך ה-Management API (הסקריפט למעלה).
  - `gh pr create` לא עובד (GraphQL חסום): פותחים PR עם `gh api repos/yosiChazan/SeeThefuture/pulls -f base=main -f head=<branch> ...`.
  - ה-clone עוקב רק אחרי ענפים מסוימים: אחרי push של ענף חדש מוסיפים
    `git config --add remote.origin.fetch '+refs/heads/<b>:refs/remotes/origin/<b>'`.
  - פעולות שמשנות הגדרות משותפות (Auth settings, תבניות מייל, חשיפת סכמה, הוספת admin) נחסמות
    לClaude: נותנים ליוסי הוראות לעשות בעצמו.
- **אבטחה ופרטיות (חובה):**
  - אף פעם לא מדביקים בשיחה טוקן, מפתח או סיסמה. טוקנים נשמרים כסודות בסביבה.
  - מספרי כרטיס, CVV, PIN וסיסמאות בנק לא נשמרים לעולם (Bitwarden).
  - ייצוא Airtable, קובצי איתי ודוחות אמיתיים מכילים מידע אישי: לא נכנסים לריפו. fixtures
    מקבלים שמות בדויים. **לפני כל commit סורקים שאין שמות אמיתיים של לקוחות** (קרה פעמיים).
  - עמודות תעודת זהות (CNP/PIN/ID) לא נקראות בכלל.
- **אחרי מיזוג PR:** לא מוסיפים commits לענף שמוזג (קרה עם PR 22); לבדוק `merged` לפני push, ועבודה חדשה
  בענף חדש מ-main.
- **התראה בסוף כל תשובה:** יוסי ביקש לקבל התראה למסך כשכל תשובה מסתיימת: בסוף כל תור שולחים
  `PushNotification` עם שורה קצרה על מה שהסתיים או מה מחכה לו.
- **סגנון:** הודעות למשתמש בעברית, קצרות, עם קישור ל-PR המלא. כל החלטה חדשה נרשמת ב-SPEC §10.

## 5. מחכה ליוסי

- **אימות במייל (החלטה 88):** (1) לפרוס את פונקציית ה-Edge `email-code` (הקוד ב-`supabase/functions/email-code/index.ts`,
  Verify JWT דלוק). (2) בתבנית Magic Link להוסיף `{{ .Token }}`. (3) לחבר SMTP ב-Supabase (Authentication → Emails → SMTP),
  אחרת הקוד מגיע רק לחברי הצוות של הפרויקט ועד 2 מיילים בשעה.


- להוסיף ב-Supabase → Authentication → Emails → **Magic Link** את השורה `הקוד שלך: {{ .Token }}`,
  אחרת איפוס דוחות איתי לא יקבל קוד במייל. שירות המייל המובנה שולח רק 2 מיילים בשעה.
- בטופס של ירח ("דוח חדש" → ירח → "עריכת הדירות"): לסמן את הדירות שלו ולהזין שכירות צפויה לכל אחת.
  חסר מידע: חלוקת 38,000 ₴ בין 7 הדירות במרכז אודסה, ואילו 10 מ-14 הדירות בארקדיה מושכרות
  (במערכת רשומות רק 9 דירות בארקדיה).
- בטופס של ליאנה: לסמן את 17 הדירות שלה ב-Alliance (במערכת יש 22 דירות Alliance; השאר של המלון).
- שאלות פתוחות ב-SPEC §11: 18 (שלושה חוזים ברומניה בלי נכס), 20 (דירה 4(43) אצל גרשון),
  22 (בניין שגוי לדירה ברומניה; BIG/SMALL), 23 (דירה 7 ב-Vasile Lascar 6 של אורבך: מה נמכר ולמי),
  24 (אוקראינה: מה לא יובא מהקבצים של קייב בגלל קונפליקטים).
- **דף הקונפליקטים של קייב** (17 קונפליקטים, נבנה מחוץ ל-repo כי יש בו פרטי לקוחות): להחליט ולשלוח את קובץ ההחלטות.
  אחר כך מייבאים את מה שנשאר בחוץ (SPEC שאלה 24).
- תאריכי רכישה אמיתיים לנכסים שמופיעים עם "לא ידוע" (החלטה 60).
